# بررسی و شروع انتقال Rovunet به macOS

این ممیزی اولیه با یادداشت‌های جاری dev.3 تکمیل می‌شود: [تغییرات](DEV3-FA.md)، [وضعیت](STATUS.md) و [آزمون‌ها](TESTING.md). اعداد و موارد ناتمامِ متن قدیمی، نتیجهٔ همان مرحله‌اند.

نسخهٔ این تحویل: **0.1.0-dev.2**؛ تاریخ: **۱۱ نوامبر ۲۰۲۶**.
این تحویل مرحلهٔ توسعه است. نسخهٔ نهاییِ هم‌سطح ویندوز و آزموده‌شده روی مک هنوز
آماده نیست. سورس مک زیر macos/ در همان مخزن مرکزی قرار دارد؛ مخزن تازه ساخته نشده است.

## محیط، مسیر و مبنای سورس

- میزبان ساخت: Windows x64، build 26300؛ GPU موجود NVIDIA RTX 4060.
- ابزارهای موجود: .NET SDK 10.0.403، runtime 10.0.14، Go 1.27.3 و Git.
- مک مقصد طبق تصویر شما: MacBook Pro 14-inch نوامبر ۲۰۲۳، Apple M3 Pro،
  رم ۱۸ گیگابایت، macOS 27.0.1. شمارهٔ سریال ثبت نمی‌شود.
- مک به محیط ساخت متصل نیست؛ Xcode، امضای قابل‌اجرا روی مک و Developer ID
  در این محیط در دسترس نیستند. تصویر مشخصات، آزمون اجرای برنامه روی مک نیست.
- مقصد اصلی ذخیره H:\Rovunet-App\Mac است؛ سورس کاری در work\rovunet-app\macos
  و بسته‌ها و گزارش‌های تحویل در deliveries نگهداری و هش‌گذاری می‌شوند.
- پروژه‌های موجود Windows و Android فقط خوانده شدند. فایل‌های قبلی checkout
  مستقل نیز تغییر نکردند. کامیت توسعهٔ محلی ویندوز با انتشار فرق داشت؛ از آن
  به‌عنوان سورس باینری منتشرشده استفاده نشد.
- فهرست انتشارهای GitHub بررسی شد؛ نسخهٔ جدیدتری از دو مرجع شما پیدا نشد.

## خروجی اول: ساختار واقعی و استفادهٔ مجدد

Rovunet.Core هدف عمومی net10.0 دارد؛ وابستگی WPF، Registry یا DPAPI در آن
پیدا نشد. مدل Profile، واردسازی، config builder، فرم‌های قابل‌انتقال، اعتبارسنجی
TLS/SSH، محاسبات اشتراک، سیاست‌های resolver، Wire و آمار Xray از همان فایل‌ها
کامپایل می‌شوند. پروژهٔ مستقل مک، obj/bin را هم داخل macos نگه می‌دارد.

Rovunet.Platform ویندوز به DPAPI، ACL، WinINET/Registry، Job Object و فایل
موقت خصوصی وابسته است. معادل مک جدا نوشته شد: AES-GCM با کلید Keychain، فایل
خصوصی، بررسی هش موتور و سرپرست فرایند بدون دسترسی مدیریتی.

Rovunet.Agent ویندوز، مسیر exe، pin ویندوز و lease پراکسی سیستم داشت. Runtime
آن با مسیر و pin معماری‌دار، IPC استاندارد و موتور Darwin تطبیق داده شد. بازگردانی
پراکسی سیستم، قبل از پیاده‌سازی آن، آماده معرفی نشده است.

Rovunet.Desktop وابسته به WPF، WinForms tray، Win32 dialog و Dispatcher است.
این بخش با کنترل واقعی Avalonia بازسازی شد؛ XAML ویندوز مستقیم اجرا نشده است.
ترجمه‌های چهار زبان، فونت Vazirmatn و ابزارهای مستقل از UI مشترک‌اند.
جزئیات در [معماری](ARCHITECTURE.md) آمده است.

## خروجی دوم: صفحه‌ها و رفتار مرجع

PortraitShell، PortraitCards، HeroPanel، Appearance18، DesktopStyles،
PageNavigation و Locales، همراه Branding، StickyHero و منوها خوانده شدند.
پنج تصویر نیز از حالت نمونهٔ خود باینری منتشرشدهٔ WPF گرفته شد؛ داده‌ها و وضعیت
اتصال این عکس‌های آزمون ساختگی‌اند و نتیجهٔ اتصال تازه محسوب نمی‌شوند.

[فهرست مرجع رابط](UI-REFERENCE.md) شامل این‌هاست: نمای باریک و گسترده، سایدبار
۲۶۰ پیکسلی در آستانهٔ ۹۲۰، لوگوی هندسی R، پرچم زبان‌ها، Hero اتصال، کارت مجموعه
و مسیر، منو و زیرمنوهای عمومی و کارت‌ها، flyout افزودن، واردسازی و QR، اشتراک،
انتخاب پروتکل، فرم‌های پیشرفته، مدیریت مجموعه، خروجی، اسکن و اعتماد SSH.

انتخاب مسیر، بازکردن کارت، ویرایش و اتصال جدا مانده‌اند. اتصال دستی آزمون پینگ
یا HTTPS اجباری ندارد. «موتور اجرا شده»، «پراکسی آماده» و «عبور داده تأیید شده»
یک وضعیت نیستند. نوار وضعیت در صفحه‌های داخلی نیز دیده می‌شود و آدرس‌ها و مقادیر
فنی در فارسی LTR هستند. تغییر تم نیز نباید متن ذخیره‌نشدهٔ فرم قبلی را از بین ببرد.

سه عکس تم شما در مرجع خصوصی پروژه نگهداری شدند؛ داخل بستهٔ عمومی کپی نمی‌شوند.
تم روشن، تیرهٔ آبی و مشکی با هویت ویندوز تطبیق داده شده‌اند. تطبیق نهایی همهٔ
صفحه‌ها، template برجستهٔ کامل، فوکوس، لمس/trackpad و اندازه‌های مختلف هنوز تمام نیست.

## خروجی سوم: معماری مک و GPU

برای نمایشگر ۱۴ اینچی شما، اندازهٔ پیش‌فرض پنجره ۵۶۰×۷۶۰ و حداقل آن
۴۸۰×۵۶۰ پیکسل منطقی است؛ فضای کاری نمایشگر و ضریب Retina در محدودکردن
اندازه لحاظ می‌شوند. اندازهٔ عادی پنجره ذخیره می‌شود. نوشتهٔ بلند در کارت،
نام مجموعه و وضعیت اتصال به خط دوم نمی‌رود: داخل کادر خودش به‌صورت قطاری
حرکت می‌کند و با نگه‌داشتن نشانگر متوقف می‌شود. متن کوتاه ثابت می‌ماند؛ آدرس
فنی چپ‌به‌راست است و ارتفاع کارت مسیر تغییر نمی‌کند.

انتخاب، C#/.NET در چهار لایهٔ Core، Platform، Agent و Desktop با Avalonia
12.1.6 است. موتور Go موجود برای Darwin/arm64 و Darwin/x64 ساخته شد. کل برنامه
به Go یا Swift بازنویسی نشده است.

رندر macOS با اولویت Metal و سپس OpenGL/software تنظیم شده است. این تنظیم
امکان شتاب‌دهی GPU می‌دهد؛ رندر headless و وجود RTX 4060، اندازه‌گیری Metal،
نرخ فریم یا مصرف انرژی مک شما نیستند. فونت لاتین/چینی fallback بومی دارد؛ فونت
اختصاصی Windows بدون مجوز بازتوزیع نشده است.

هدف پشتیبانی macOS 15 به بالا است؛ وضعیت پشتیبانی .NET و حداقل باینری‌ها با هم
بررسی شدند. دستگاه مقصد طبق تصویر macOS 27.0.1 دارد. پذیرش اجرایی این دستگاه
هنوز لازم است. Apple Silicon اولویت دارد و Intel جدا ثبت می‌شود.

برای TUN، مسیر packet tunnel system extension متناسب با توزیع مستقیم بررسی شد.
طبق [TN3134 اپل](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment)،
packet-tunnel app extension مک محدودیت App Store دارد. طراحی extension/helper،
entitlement، مسیردهی و بازیابی سراسری هنوز اجرا نشده‌اند. تفکیک برنامه‌ها بدون
بررسی محدودیت‌های پلتفرم و managed/MDM وعده داده نشده است.

## خروجی چهارم: قابلیت‌ها و محدودیت‌ها

[جدول پنج‌ستونی قابلیت‌ها](CAPABILITIES.md) واردسازی، فرم دستی، موتور Darwin،
عبور داده و وضعیت بسته را جدا نشان می‌دهد:

- Xray و NaiveProxy واقعی Darwin هر دو معماری بررسی و در بستهٔ توسعه قرار گرفتند.
- helper Go و supervisor واقعی Darwin هر دو معماری ساخته شدند.
- Slipstream و OpenSSL خصوصی بسته‌بندی و وابستگی‌ها به @loader_path منتقل شدند؛
  عبور دادهٔ واقعی روی مک هنوز آزموده نشده است.
- Hy2 و WireGuard با وجود adapter سالم فرض نشده‌اند و آزمون مک ندارند.
- SS2022، Hy2 hopping، AWG، cs/fm و Tor در مسیر مک و موتورهای Darwin اضافه شده‌اند؛
  بازیابی هوشمند و پذیرش عبور دادهٔ هر پروتکل روی مک هنوز باقی‌اند.
- System Proxy در dev.2 برای آزمون مک پیاده شده است؛ TUN، E2E کامل اسکن و برخی فرم‌ها و رفتارهای Windows ناتمام‌اند.
- حجم و انقضای ارائه‌دهنده از شمارندهٔ محلی جداست؛ نبود اطلاعات «نامشخص» می‌ماند.
- AnyTLS، TUIC و Mieru آماده معرفی نمی‌شوند.

## اعتبار تحویل

نسخه، سورس مبنا، فایل‌ها، هش‌ها و دامنهٔ آزمون همراه هر بسته ثبت می‌شوند.
[آزمون‌ها](TESTING.md) و [کارهای باقی‌مانده](BACKLOG.md) را پیش از نتیجه‌گیری
دربارهٔ پشتیبانی بخوانید. بستهٔ cross-build توسعه، نصب پذیرفته‌شدهٔ مک، Developer ID،
notarization یا DMG نهایی نیست. امضای محلی ad-hoc نیز آن را به نسخهٔ عمومی تبدیل نمی‌کند.

هیچ push، PR، merge، workflow، tag یا انتشار عمومی انجام نشده است. ادامهٔ کار به
آزمون همین خروجی روی مک و تکمیل مرحله‌ای جدول نیاز دارد. موفقیت یک اتصال نمونه،
پایان پروژه محسوب نمی‌شود.

وضعیت تازهٔ بسته، اصلاحات و آزمون‌های دقیق در DEV2-FA، CAPABILITIES و TESTING ثبت شده‌اند.
