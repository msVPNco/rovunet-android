# پچ ۲۰۲۶-۱۱-۰۹ — پیام وضعیت حساب هنگام خطای فید

## چه چیزی تغییر کرد

فقط `src/Rovunet.Desktop/MainWindow.cs` در `work\windows`.

هنگام **Update/Import** اشتراک، اگر فید با `404` برنگردد ولی فایل وضعیت
(`.status.json`) بگوید حساب `expired` یا `limit_reached` است، پیام خطا
به‌جای «فایل پیدا نشد» وضعیت واقعی حساب را نشان می‌دهد.

### قبل

```csharp
catch (Exception e) { preview = null; error.Text = L.Text(e is SafeError se ? se.Code : "FETCH_FAILED"); }
```

### بعد

```csharp
string FeedError(string code, string sourceId)
{
    if (code == "STATUS_NOT_FOUND" && statuses.TryGetValue(sourceId, out var snap))
    {
        var view = snap.Evaluate();
        if (view.Status?.State == "expired") return L.Text("ACCOUNT_EXPIRED");
        if (view.Status?.State == "limit_reached") return L.Text("ACCOUNT_LIMIT");
    }
    return L.Text(code);
}
```

و در دو `catch`:

```csharp
error.Text = FeedError(e is SafeError se ? se.Code : "FETCH_FAILED", SourceOf(input.Text));
```

## چرا

از پنل ۱.۱۹، کاربر متوقف‌شده **فید ندارد ولی فایل وضعیت دارد** (پنل ۱.۲۰.۱ هم همین قرارداد را دارد).
قبلاً کاربر «زمان تمام‌شده» پیام «فایل پیدا نشد» می‌دید که هم گمراه‌کننده بود و هم
متن آن صریحاً می‌گفت «این خطا انقضا را ثابت نمی‌کند» — در حالی که وضعیت حساب دقیقاً همان را می‌گفت.

## آزمون پیشنهادی

1. در پنل یک کاربر تست با انقضای گذشته بساز (یا `users renew` با صفر روز).
2. در برنامه، اشتراک همان کاربر را باز کن و **Update** بزن.
3. انتظار: پیام «زمان حساب پایان یافته» — نه «فایل پیدا نشد».
4. همان تست با کاربر «حجم تمام‌شده» → «حجم حساب پایان یافته».
5. کاربر حذف‌شده (نه متوقف) باید همان `STATUS_NOT_FOUND` قبلی را نشان دهد.
6. بازگشت به حالت عادی: کاربر سالم → Update باید مثل قبل `UPDATE_READY` بدهد.

## نکات باز

- **چندآدرسی (پنل ۱.۱۷+):** در اعمال اشتراک، `ToDictionary(p => p.ItemId)` اگر پنل برای
  کانفیگ‌های یک تونل در آدرس‌های مختلف `ItemId` یکسان بدهد، استثنا می‌دهد و به `FETCH_FAILED`
  می‌رسد. با یک اشتراک واقعی چندآدرسی آزمون شود؛ اگر تکرار بود، کلید باید
  `ItemId + host` شود.
- **`reality2`:** هیچ حذف بر اساس نام در کد پیدا نشد (گروه‌بندی با `Id`/`SourceId` است)،
  پس نیازی به تغییر نبود؛ فقط در آزمون واقعی مطمئن شو هر دو هسته در یک مجموعه می‌مانند.
