# Local preview.13 — independent Panel status2 adapter

This is a continuation of the four ACTIONS03 macro actions, not their acceptance or a public release. Feed bodies on the canonical `/v2/sub/<32 lower-case hex>.json` and `.windows.json` paths remain version 1. Only their exact `.status.json` and `.windows.status.json` companions select the independent version 2 DTO. Legacy `/sub/` and status1 remain explicit, separate paths. Query, encoded, normalized/aliased paths and cross-authority guessing are refused. Existing HTTPS, redirect and endpoint-identity protections remain in force.

The DTO reads integral JSON tokens directly into Int64: no float intermediary, string coercion or clamping. Boundary tests cover 2^53+1, MaxInt64, MaxInt64+1, fractions, strings, negatives and null. The copied Panel schema is an immutable input; its oversized numeric maximum does not enlarge the client range. `limit_kind`, `expiry_kind`, nullable confirmed/pending, coverage, measurement, sampled/generated times and hold/archived states remain distinct. Confirmed is an accounted lower bound; pending alone cannot imply exhaustion. Missing up/down are not invented. A known total or expiry remains visible when usage is unknown. The client does not calculate an authoritative remaining balance from partial confirmed counts.

Private status body, schema discriminator, per-source binding/checkpoint, origin and the shared authority index are saved in one existing atomic CurrentUser-DPAPI store transaction before publishing the result to the UI. Save failure rolls these fields back. The shared index is keyed by canonical HTTPS origin plus server/account IDs, with revision/confirmed high-water per period. Token and default/Windows format aliases share that authority. An explicit URL rotation of an existing source carries its own checkpoint; an unrelated origin is never automatically assigned another provider's authority. A missing required index/checkpoint fails closed, including through a newly added token alias. This is local rollback protection, not protection against an authorized user restoring an entire old encrypted store.

Bindings cannot change merely by increasing revision. Same-revision semantic changes, revision/confirmed regressions, retired-period replay and backwards generation time are refused. HTTP Date is required for status2; future generation is rejected and cached data is labelled stale. Sampled time is never substituted with generated time. Request epochs plus original source URL/reference checks suppress late and concurrent replies. A newer alias invalidates the older in-memory snapshot. Headers cannot replace the private body/high-water. 404, 503, redirects, malformed bodies and unavailable persistence preserve the previous body and profiles; there is no trusted status1/header fallback for status2. A status2 update error stops feed replacement. The legacy same-account renewal with a higher revision remains compatible.

SourceID and ItemID preservation, pins, local overrides and selection are exercised across explicit token rotation and reorder. Endpoint guards remain active. `SubscriptionMigrationPreview` still only describes an explicit decision; no new migration Apply/credential/pin trust transfer was implemented. Panel's order-dependent `-ipN` limitation remains open; tests of stable fixture IDs do not resolve it. SQLite accounting remains exclusively a Panel responsibility.

Targeted checks: `dotnet run --project tests/Rovunet.Tests -c Release` (375 checks), `Rovunet.exe --ui-status21 <new absolute JSON path>` (378 mock-HTTP/private-store/WPF assertions), `--ui-selection17` (10 connection-history assertions), and `--ui-review09 <REVIEW09 inputs> <new report>` (44 legacy assertions). These are fixture assertions, not hundreds of independent live network tests. Reported quota strings are actual fa/en/ru/zh-CN translations under all three themes. Execution receipts and final loaded-assembly hashes are delivered outside the source archive.

The preview.12 collapsed-header clipping fix is retained. The latest owner correction supersedes its selection-based ordering: a single click only selects. Successful connection records the persistent most-recently-connected history and moves that child and its parent first; unsuccessful/merely selected paths do not update the history. The active path stays first and older connected paths retain their relative history after restart. UI reports are separate from the manager's contract report.

No VM was resumed, and no host route/DNS/SCM/WFP/reboot was changed for this work. Native pilot18/tools4 have their own frozen source and hashes. Their boot/capture/SCM/IPC race acceptance, service SYSTEM-to-LocalService DPAPI, independent AWG/SS2022 peers/cold payload and publisher/live update acceptance are still open. Consumer UI/mock tests do not close those gates. Public 0.1.1 Beta and the owner's active installation are not replaced by producing this package.

Historical Hy2 failure notes describe older versions. The owner's later successful Hy2 observation is preserved; exact version/network details were not independently recorded, and neither current failure nor universal connectivity is inferred.
