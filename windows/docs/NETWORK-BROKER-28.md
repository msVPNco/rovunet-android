# TUN / kill-switch acceptance gate

Owner's later instruction explicitly authorized doing as much actual TUN/kill-switch work as possible. A real bounded Windows backend and isolated-lab controller now build in experimental/, beyond the original model: native routes/DNS, persistent WFP, protected journal, same-SID/PID/installation verification and fixed pinned-Xray TCP/DoH TUN. Its self-test reads Windows routes/listener PID without mutations; pinned Xray accepts the config without starting. Wintun0.14.1 was subsequently downloaded, archive/DLL hashes matched and original Windows signature verified Valid. See experimental/README.md for exact current limits and the separate lab package. It is not deployed/enabled by the consumer installer.

This build still exposes local HTTP/SOCKS5 and optional current-user WinINET proxy. It does not install a service/driver or claim device-wide routing, app interception or a kill switch.

The independent specification in `prototypes/NetworkBroker28` exercises a constrained versioned request, bounded loopback port, session ownership, journal-before-mutation, separate opt-in protection, loss/recovery and refusal to overwrite another network owner's settings. It is excluded from the installer. Its passing model is not a Windows routing/leak test.

The production broker must be installed in administrator-controlled Program Files with an installation identity. Its authenticated pipe needs a restricted service DACL, verified client SID and PID/image/integrity, replay/session protection and bounded framing. The ordinary WPF/Agent cannot supply an executable, command line, DLL, arbitrary route, DNS server or service name. Resolve native paths from the protected installation; pin hashes before loading. Do not copy the unprivileged Agent trust model into a LocalSystem service.

Plan: fixed Rovunet adapter GUID/name; persist original/applied IPv4/IPv6 routes, interface LUID, metric and DNS together with ownership/session. Bypass only pinned upstream endpoints plus loopback/DHCP/ND required for bootstrap; avoid the TUN routing itself. Preserve another app's/user's route changes on conflict. Startup recovery, crash, reboot, network change, upgrade and uninstall must reconcile this journal. New interfaces/IPv6 must be covered rather than silently leaked. Current public SOCKS UDP is disabled, so a TUN cannot promise UDP merely by forwarding that listener.

Kill switch is separate opt-in WFP policy. Protect before routing; on process crash/network loss retain the narrowly scoped fail-closed policy. Restore only owned network changes before releasing protection on explicit stop. On conflicting ownership retain recovery information and offer an explicit repair/exit path. A catch-all allow filter or turning protection off on tunnel crash does not pass. Service stop/uninstall needs a tested recovery path.

Driver candidate: official Wintun0.14.1 signed redistributable (https://www.wintun.net/), upstream archive SHA256 `07c256185d6ee3652e09fa55c0b673e2624b565e02c4b9091c79ca7d2f24ef51`; now downloaded/verified for the separate lab, not installed on this host or advertised as an active consumer feature. Follow official WFP ALE guidance: https://learn.microsoft.com/en-us/windows/win32/fwp/ale-layers . A user-created/self-signed publisher root is not a public-signing substitute.
