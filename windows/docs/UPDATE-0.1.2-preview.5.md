# Windows0.1.2-preview.5 — maintenance review

The owner adopted the full Windows maintenance plan and requested a local build while away. The prior local/public releases, owner profiles/install, Android/Mac/panel code and public GitHub assets remain separate. This is not a new publication.

Implemented: red failure/disconnection text while preserving inconclusive-test meaning and neutral pending/cancel states; larger high-contrast vector ellipses inside44DIP targets without moving menus; direct encrypted Mahsa feed with ASCII AES128CBC/PKCS7 decoding and existing strict import; pre-request old-Hiddify migration, same subscription identity, atomic replacement/failure preservation; managed Mahsa/Anonymous names without rawURL inputs/details/copy; Patterniha preset/fetch route removal. Explicitly rejected independent entries remain reported; an invalid native envelope or empty usable result never erases a subscription.

About update button now begins an in-app Windows x64 version check. Connected routes through the active local HTTP proxy; disconnected checks directly. Download validates exact release/platform/version/channel/asset size/hash and restricted HTTPS redirects before atomic save. Network failure/cancel permits retry. No automatic execution/installation or trusted signed-manifest claim. See UPDATER-28.md.

DPAPI remains user-bound. Writes now use unique owner-only transients, bounded serialization/read and atomic replacement; plaintext native buffers are cleared and encrypted null is rejected rather than treated as first run. IPC additionally rejects duplicate/unknown JSON properties and verifies both pipe-peer PIDs. Existing random names, CurrentUserOnly, parent directory, command allowlist, pinned engines and probe isolation remain.

Upstream review found a SOCKS domain-length overflow fixed after the pinned Mihomo commit. Backported upstream6780eeeb plus its exhaustive regression, rebuilt AWG/extra helpers, changed their enforced hashes and shipped patched corresponding source. Xray/Naive/Slipstream/transports/Tor remain pinned. No general claim of advisory absence. See native-patches/mihomo and supplemental-pins.json.

Versioned out-of-band capabilities/strict feed fixtures and a read-only panel handoff are included. Native v1 schema is unchanged. Portable validation script and pinned-action CI integration template are prepared; the template is not represented as already active in the canonical repository. Offline signing preparation requires a real approved certificate/publisher and timestamp; no signing identity is invented.

Acceptance follows the exact delivered source/installer hashes and final reports, not these pre-build notes. UI fixtures cover all four languages and three themes, DPI rasterization, download/failure preservation and existing About live translation. Controlled Windows Agent/HTTPS, native encrypted relays and installer/upgrade guards must pass before delivery. Synthetic fixtures never load/save the owner's profiles or install test certificate roots.

Still open: production privileged TUN/service/WFP implementation and real leak/crash/recovery acceptance (the separate prototype is only a model); trusted publisher signing and automatic verified installation; physical laptop/touch/mixedDPI/sleep/network-change tests; external-provider breadth/Tor bootstrap. HY2/stockWG work has a recorded conflict with the owner's earlier explicit deferral; the document says not to revive cancelled work automatically. Do not label them fixed. Per-item status and continuation are in development/TASK-LEDGER.json and the delivery report.

Rollback: keep the previous0.1.2-preview.4 local installer/source and published0.1.1 untouched. Normal upgrade uses cooperative target-owned exit and preserves DPAPI data. Back up encrypted data before a deliberate downgrade, retain its original byte identity, and do not overwrite newer stores merely to force an older binary to start. Failed update-download/subscription refresh does not require a rollback because its previous data/file is preserved.

Later owner-authorized expansion: actual experimental TUN TCP/DoH + separate persistent-WFP broker now builds, beyond the original model. It is VM/machine-marker gated, has a separate lab controller and verified original Wintun binary. It is not enabled/deployed in the normal app; full UDP, service/upgrade/recovery integration and privileged real leak/crash/sleep acceptance remain open. See experimental/README.md and exact lab verification for what ran without network mutations.

Final data-preservation review: Mahsa differs from general public-list preview. Any rejected Mahsa config (including a mixed valid/invalid batch) blocks applying or replacing the collection; rejection counts/reasons remain visible and existing data stays unchanged. A preview with eight accepted and two TLS_UNVERIFIED rows is not successful replacement. Both new import and one-click update enforce this rule. Anonymous and other independent-source partial preview behavior is unchanged.
