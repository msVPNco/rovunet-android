# Windows 0.1.2-preview.14

Collection cards now separate the closed header from expanded quota/test details and profile rows. A closed header targets 72–88 DIP, depending on available status; profile cards are fixed at 66 DIP with 44-DIP action targets. No whole-interface/text scaling is used. Shadows, edges and profile-action strokes are lighter. Missing account information does not reserve a tall blank quota panel or imply unlimited allowance/no expiry.

One persisted `OpenCollectionId` is authoritative. The old boolean map is retained as a normalized compatibility mirror; legacy multiple-open data chooses one valid stable key deterministically. Both card arrows/identity buttons and collection-menu toggles use one transaction. Opening B closes A; closing B permits all closed. Save failure restores both the prior ID and entire compatibility map. Migration normalizes in memory before rendering; the next ordinary successful Save persists it without an extra startup disk write. Profiles, account checkpoints, selection, pin and overrides are not changed by expansion.

Search filters without implicitly expanding every matching group. Home refresh, page return, language/theme rebuilds, successful-connection reorder and restart preserve zero-or-one expansion. The connection hero and footer are independent of the collection accordion. Single click still selects only; successful connection still records the MRU order introduced in preview.13. Closing a group hides presentation, not its profiles or errors.

The focused `--ui-accordion26 <new absolute report path>` harness exercises four synthetic subscriptions (finite, time-limited, unknown, unlimited), a long profile name and eight-profile collection. It covers arrow/menu A→B→close, legacy normalization, Save rollback, search, nested-page return, restart, connection-state reorder, four languages, three themes and 480/1120-DIP widths. Images and a short sequence are actual native WPF renders using synthetic data, not a bitmap redesign or live-network recording. The report records host DPI; exported client-area PNGs use the existing 96-DPI rendering helper. No physical-touch or mixed-monitor measurement is inferred. The existing ten connection-order checks are also relevant; the historical 800-assertion suite is not rerun just for counts.

Panel Review22 uses the same feed1/status2 wire contract. No parser reset, new authority key, trusted static/status1 fallback or account migration Apply was added. HTTP 404/502/503 remain errors that preserve cached state with stale/unknown labels, not proof of account expiry. Panel Review20 has reported stable address maps/tombstones; Windows primary-address/trust and migration acceptance remain separate. Historical notes about order-dependent -ipN describe the earlier Panel state.

WIN24-STATUS2-NUMBER-FORMS-01 remains P2: this client accepts canonical integer lexemes, matching the current emitter; schema-permitted forms such as 1.0/1e0 need a coordinated exact-integer implementation later. Float64/coercion/clamping were not introduced for this UI release.

This is an x64 consumer prerelease. Native pilot18/tools4, boot/WFP/TUN/kill-switch, service-specific DPAPI, independent peer/cold-payload and publisher/live-updater gates remain independent and do not block honest proxy-only publication. Owner installation is not automatically replaced by publication. Only public installer/source/checksums/release notes are publication assets; managerial archives and private fixture stores are excluded.
