# تصمیم‌ها و دامنهٔ اصلاحات review03

این سند دربارهٔ تغییرات محلی پس از review02 است. انتشار عمومی، ساخت مجدد کتابخانه‌های native و اجرای workflow روی میزبان GitHub انجام نشده‌اند.

## دو باگ گزارش‌شده روی گوشی

۱. انتخاب SSH فقط در ViewModel بود و انتخاب کارت مجموعه آن را خالی می‌کرد. حالا آخرین انتخاب هر مجموعه جدا نگه داشته و به‌صورت رمز‌شده ذخیره می‌شود. برگشت به مجموعه یا بازکردن دوبارهٔ اپ، مسیر انتخابی را به Naive تبدیل نمی‌کند. اتصال دستی همچنان به تست اجباری وابسته نیست؛ شکست تاریخی تست مانع تلاش مستقیم همان مسیر نمی‌شود. انتخاب خودکار، شکست تازهٔ همان شبکه را نادیده نمی‌گیرد.

۲. توکن جدید بررسی حذف (`deletionReview`) ناخواسته در کلید مقایسهٔ کانفیگ حضور داشت. فعال‌سازی، ثبت زمان اتصال و مرتب‌کردن SQL توکن را عوض می‌کرد؛ در پایان تست گروهی، `ProbeCache` نتیجهٔ کانفیگ سالم را پاک می‌کرد. توکن فقط از کلید مقایسه حذف شد؛ بررسی کامل ردیف و ciphertext در حذف تراکنشی دست‌نخورده است. خود تست دیگر active profile پایدار یا آخرین اتصال کاربر برای میان‌بر/راه‌اندازی خودکار را عوض نمی‌کند.

نتایج کامل هر مسیر، زمان تست و جمع نتایج مجموعه نمایش داده می‌شوند. ذخیرهٔ رمز‌شده سقف ۲۰۰۰ نتیجه و هفت روز دارد. Pending/Testing و resolverهای کشف‌شده ذخیره نمی‌شوند. تغییر تنظیم مؤثر یک کانفیگ، فقط شاهد همان کانفیگ را نامعتبر می‌کند. تغییر شبکه و بازگشت به اپ نتیجه را تاریخی می‌کنند؛ تاریخی بودن آشکار است و موفقیت شبکهٔ فعلی تلقی نمی‌شود. معیار تأخیر بر حسب میلی‌ثانیه است، نه اندازه‌گیری سرعت دانلود.

## ارزیابی ۱۹ پیشنهاد

| بند | رأی و اقدام |
|---|---|
| ۱. Orchestrator سرویس | مشکل تکرار مسیرها وارد است. بازنویسی هم‌زمان single/chain/recovery را در این بسته انجام ندادم. پیش‌شرط پذیرش: تست آماده‌سازی/شکست/لغو هر سه مسیر برای هر آداپتر، سپس انتقال یک پروتکل و مقایسهٔ رفتار. کوچک بودن diff به‌تنهایی اثبات کم‌خطر بودن این جابه‌جایی نیست. |
| ۲. تفکیک Repository | وارد؛ استخراج state و launcher باید همان session ownership و ترتیب توقف را حفظ کند. این مرحله هم‌زمان با ترمیم انتخاب/نتایج انجام نشد. |
| ۳. جداسازی parser و use-case اسکن | جهت درست است، ولی تمام ConfigImporter خالص نیست: رمزنگاری، قفل و قید دستگاه هم دارد. جداسازی باید مرز parse/validate/decrypt را صریح کند؛ انتقال پوشه به‌تنهایی اصلاح معماری نیست. |
| ۴. TUN مرده | اعمال شد: سه فایل موتور حذف شدند. `ResolverConfig` زنده بود؛ امضای قبلی آن در فایل مستقل حفظ شد. |
| ۵. کلید رشته‌ها | تمام متن‌های تازه کلید معنایی ثابت دارند. گیت ترجمه از چند صفحه به همهٔ ۴۴۹ منبع قابل‌ترجمه گسترش یافت و سه ترجمهٔ قدیمیِ جاافتاده تکمیل شد. صرف ویرایش متن انگلیسی، تا وقتی شناسه را تغییر ندهیم، ترجمه را یتیم نمی‌کند. |
| ۶. SPKI | اعمال شد، با مهاجرت fail-closed از leaf pin قبلی. تمدید با همان کلید پذیرفته می‌شود؛ تغییر کلید یا ناهماهنگی گواهی قدیمی رد می‌شود. ادعای «در همهٔ مدل‌ها امن‌تر» مطلق نیست. |
| ۷. قفل دستگاه/StrongBox | اجبار پیش‌فرض رد شد: بازیابی VPN در صفحهٔ قفل باید به رمز دسترسی داشته باشد. Android 12–14 نیز برای unlocked-device-required باگ‌های حذف/دسترسی کلید دارند. vault lock اختیاری و StrongBox با fallback موضوع مستقل‌اند. |
| ۸. Network Security Config | اعمال شد: HTTP سطح بالای بیرونی ممنوع و loopback مستثناست. طبق مستند Android این سیاست روی raw Socket/native تضمین سراسری نمی‌دهد؛ پروتکل‌ها و بررسی هویت خودشان همچنان لازم‌اند. |
| ۹. محدودیت تلاش LAN | اعمال شد: پنج شکست احراز هویت در دقیقه برای هر IP و سقف درخواست‌های احراز هم‌زمان. مسیر محلی TUN و اتصال‌های صحیح به پنج جریان در دقیقه محدود نمی‌شوند. همهٔ هشت پل SOCKS مبتنی بر JVM و HTTP proxy از همین کنترل استفاده می‌کنند. این کنترل جای حفاظت در برابر همهٔ انواع DoS یا رمزنگاری ترافیک اشتراک LAN را نمی‌گیرد؛ نام کاربری/رمز در SOCKS/HTTP ساده به‌تنهایی امنیت شبکهٔ عمومی را تضمین نمی‌کند. |
| ۱۰. فاز اتصال | پیشنهاد وارد است؛ نمایش resolve/verify بدون رویداد واقعی همان فاز می‌تواند گمراه‌کننده باشد. اتصال این فازها به همهٔ single/chain/recovery در این بسته انجام نشد و نباید به معنی تغییر شرط Connected باشد. |
| ۱۱. ErrorCode | وارد؛ باید تدریجی در مرز سرویس و UI جایگزین رشته شود. خطای فنی و علت شکست تست نباید با پیام عمومی گم شوند. تغییر سراسری taxonomy در این بسته انجام نشد. |
| ۱۲. HTTP 204 | متن تازهٔ تست سریع/پایداری صریحاً HTTPS 204 معتبر را می‌گوید؛ راهنما توضیح می‌دهد پاسخ دیگر، عدم تأیید هدف تست است و به‌تنهایی مرگ تونل را اثبات نمی‌کند. پذیرفتن 200 دلخواه یا حذف بررسی گواهی راه‌حل نیست. |
| ۱۳. تست‌های Gradle | شروع واقعی اعمال شد: سه قرارداد انتخاب/فاز تست/watchdog به `app/src/test` منتقل شدند؛ تست‌های سابقهٔ نتایج و محدودکنندهٔ LAN هم همان‌جا هستند. یک مجموعهٔ JUnit واحد هم با Gradle و هم در job مستقل verify اجرا می‌شود؛ بنابراین به آماده‌بودن کلید انتشار و ساخت native وابسته نیست. جارهای تازه نیز نسخه و SHA-256 ثابت دارند. همهٔ harnessهای قدیمیِ JVM/native به JUnit منتقل نشده‌اند؛ اسکریپت‌های شبکه و قرارداد همچنان اجرا می‌شوند. |
| ۱۴. Corpus طلایی | پیشنهاد وارد است؛ باید نمونه‌های تاریخی بررسی‌شده و سیاست سازگاری داشته باشد. در این بسته corpus پوشش‌دهندهٔ همهٔ نسخه‌ها ساخته نشده است. الزام اینکه خوانندهٔ قدیمی هر نسخهٔ جدیدی را بفهمد درست نیست؛ فرمت ناشناخته باید صریحاً رد شود، نه اینکه فیلد امنیتی حذف شود. |
| ۱۵. زنجیرهٔ ساخت | `gomobile@latest` حذف و به نسخهٔ x/mobile همان go.mod مقید شد. قفل Cargo، پین همهٔ ابزارها و verification-metadata کامل هنوز بازند و باید در یک ساخت native از سورس اعتبارسنجی شوند. «برای همیشه تمام شدن» بدهی زنجیرهٔ تأمین ادعای درستی نیست. |
| ۱۶. lint/detekt | گارد افزایشی برای `!!`، `GlobalScope` و `runBlocking` در سورس اپ با baseline صریح و اجرای CI افزوده شد. این اسکن متنی جای detekt مبتنی بر AST نیست؛ مهاجرت کامل detekt/lint baseline هنوز انجام نشده است. |
| ۱۷. مهاجرت امضا | تصمیم و مسیر در ADR ثبت شد. bridge با امضای debug نمی‌تواند بررسی امضای Android را دور بزند. lineage با کلید قبلی و پشتیبانی نسخهٔ Android قابل بررسی است؛ در غیر این صورت انتقال صریح خروجی رمز‌شده و نصب جدا لازم است. کلید production ساخته یا منتشر نشده است. |
| ۱۸. کانفیگ امضاشده | امضای Ed25519 برای اصالت وارد است؛ ادعای «قفل واقعی در برابر کسی که APK را تغییر می‌دهد» نادرست است. کلاینت دست‌کاری‌شده می‌تواند بررسی را حذف کند؛ انقضا/لغو/محدودیت حساب به کنترل سرور نیاز دارد. فرمت و trust onboarding باید با پنل طراحی شوند، نه در این بستهٔ رفع اتصال. |
| ۱۹. ADR | اعمال شد: شش سند دربارهٔ قفل، مهاجرت امضا، TOFU/SPKI، حذف موتور مرده، دسترسی پس‌زمینه به کلید و انتخاب/سابقهٔ تست ثبت شدند. |

## نکات پیوست چهارم

- یکسان بودن CRC و اندازهٔ فایل به‌تنهایی اثبات رمزنگاری‌شدهٔ برابری نیست؛ بررسی قبلی ما شامل برابری بایتی/هش نیز بود.
- توکن `ProfileSnapshots.digest` فقط در حافظه و بازبینی حذف است. کلید اثرانگشتِ تاریخچه قرارداد مستقلی برای کشِ کوتاه‌عمرِ رمز‌شده است؛ هیچ توکن حذف یا پروفایل کامل در آن ذخیره نمی‌شود.
- بررسی هم‌ترازی LOAD همهٔ ELFهای ۶۴بیتی در گیت ساخت APK خودکار شد؛ این گیت بازتولیدپذیری کتابخانه‌ها را ادعا نمی‌کند.
- وقفهٔ زمان تأیید هویت فعلاً سراسری است؛ چرخهٔ تست مجموعه سریالی است. تفکیک شمارندهٔ انتظار per-attempt در این بسته انجام نشد.
- خطای HTTPS و وضعیت Connected دو مفهوم جدا هستند. اتصال دستی به همان مسیر واقعی انجام می‌شود و نتیجهٔ تاریخی با مسیر دیگری جایگزین نمی‌شود.
