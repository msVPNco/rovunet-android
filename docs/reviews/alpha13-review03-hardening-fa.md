# پیگیری بازبینی چهارم alpha13 — فقط سورس

این پیگیری روی `7cc7f0e362911dea4a862ef33e97f95bf4852b36`، پایهٔ دقیق سورس review03، انجام شد. گزارش پیوست و نکته‌های تازه با کد تطبیق داده شدند؛ بازرسی مستقل APK در این دور دوباره انجام نشد. هیچ APK، نسخه، تگ، push، انتشار عمومی یا اجرای تازهٔ workflow گیت‌هاب برای این پیگیری ساخته یا انجام نشده است.

## نتیجهٔ نقدها

| موضوع | ارزیابی و اقدام |
| --- | --- |
| سه فایل یتیم | وارد است. `NatTable.kt`، `TunInterface.kt` و `IpPacketParser.kt` حذف شدند. تمام تعریف‌های سطح بالای آن‌ها در سورس برنامه، تست‌ها و ابزارهای JVM جست‌وجو شدند و فراخوانی خارجی نداشتند؛ بعد از حذف هم ارجاعی باقی نماند و کامپایل موفق شد. |
| اعتبارسنجی پارسر قدیمی | باگ در مسیر فعال ترافیک نبود؛ حذف کد دست‌نیافتنی، امکان بازگشت تصادفی همان پیاده‌سازی ناقص را برطرف می‌کند. ادعای تعمیر و فعال‌کردن پارسر نداریم. `ResolverConfig` که استفادهٔ زنده دارد حفظ شد. |
| IPv4 و IPv4-mapped IPv6 | تقویت دفاعی وارد است. نگاشت صریح ۱۶‌بایتی پیش از تشخیص loopback و تولید کلید شمارنده به IPv4 تبدیل می‌شود؛ هیچ DNS lookup انجام نمی‌شود. ورودی mapped معمولاً توسط APIهای متداول Java به IPv4 تبدیل می‌شود؛ بنابراین دورزدن در مسیر واقعی socket اثبات نشده است. تست عمداً یک `Inet6Address` صریح می‌سازد تا حالت باقی‌مانده را پوشش دهد. |
| هشدار ظرفیت ۵۱۲ IP | وارد است. هشدار ثابت و فاقد IP، نام کاربری یا رمز، حداکثر یک‌بار در ۶۰ ثانیه با ساعت یکنواخت ثبت می‌شود. ثبت لاگ بیرون از قفل شمارنده است. پرشدن ظرفیت همچنان ورودی تازه را موقتاً رد می‌کند. |
| توصیف LRU | نیازمند تصحیح بود. حتی پیاده‌سازی قبلی ورودی زنده را برای جا دادن IP تازه حذف نمی‌کرد؛ access-order بودن `LinkedHashMap` به معنی eviction نبود. اکنون `HashMap` استفاده می‌شود تا این رفتار صریح باشد. انقضای ورودی فقط وقتی مجاز است که احراز هویت معلقی نداشته باشد. |
| پیشنهاد اصلاح‌شدهٔ ۱۴ | وارد است و یک ایراد واقعی را آشکار کرد: review03 هنوز نسخهٔ بزرگ‌تر از ۳۳ را با پارسر ۳۳ می‌خواند و فقط هشدار می‌داد. این fallback حذف شد. نسخهٔ ناشناخته، از جمله نسخهٔ آینده با قید امنیتی جدید، صریحاً رد می‌شود. |
| یکسانی کتابخانه‌ها با CRC و اندازه | به‌تنهایی اثبات رمزنگاری‌شده نیست. شواهد SHA-256 ثبت‌شدهٔ دور قبلی مبنای یکسانی محتواست؛ این دور ادعای بازرسی باینری تازه ندارد. |

## قرارداد ورود کانفیگ

- نسخه‌های شناخته‌شده از ۱ تا ۳۳ مسیر صریح خود را دارند؛ هر نسخهٔ ناشناخته یا برچسب نسخهٔ نامعتبر خطای `Unsupported version` می‌دهد و پروفایل قابل استفاده تولید نمی‌کند.
- در ورودی مخلوط، ردیف سالم طبق رفتار قبلی قابل ورود است و ردیف پشتیبانی‌نشده همراه هشدار کنار گذاشته می‌شود. واردکردن همهٔ ردیف‌ها به‌صورت اتمی، قرارداد این تابع نیست.
- پس از رمزگشایی bundle نیز همین سیاست برقرار است. قالب جدید به قالب قدیمی تنزل داده نمی‌شود.
- حفظ قفل، هش، انقضا، اجازهٔ اشتراک، قید دستگاه، resolver پنهان، شناسهٔ مجموعه و اعتبارنامه‌های دارای `|` و Unicode در نمونه‌های مربوط بررسی می‌شود. در نمونه‌های منفیِ آزموده‌شده، دستگاه متفاوت، هش قفل نامعتبر و اعتبارنامهٔ JSON ناقص یا قطع‌شدهٔ نسخهٔ ۳۳ به حالت مجاز پیش‌فرض تبدیل نمی‌شوند.

## نمونه‌های ثابت و اجرای تست

`app/src/test/resources/import-corpus/cases.json` پنجاه نمونهٔ **مصنوعی و ثابت** دارد؛ هیچ خروجی شخصی یا اعتبارنامهٔ سرور واقعی در آن نیست:

| دسته | تعداد |
| --- | ---: |
| نمونهٔ قابل‌خواندن برای هر نسخهٔ ۱ تا ۳۳ | ۳۳ |
| نمونهٔ محدود با قیود امنیتی در نسخه‌های مربوط | ۷ |
| نسخهٔ ناشناخته، آینده، overflow یا برچسب نامعتبر | ۶ |
| دادهٔ امنیتی ناقص یا نامعتبر | ۴ |

این‌ها خروجی جمع‌آوری‌شده از همهٔ انتشارهای تاریخی نیستند و همهٔ ترکیب‌ها، پروتکل‌ها یا فیلدهای اختیاری را پوشش نمی‌دهند. نمونه‌های ثابت از exporter تحت آزمون تولید نمی‌شوند. یک تست جدا نیز round-trip خروجی فعلی را می‌آزماید. هنگام افزودن نسخهٔ بعدی باید نمونه‌های مثبت و منفی آن عمداً اضافه شوند.

برای اجرای خودِ importer/exporter در تست استاندارد Gradle، فقط کدک Base64 این دو فایل از وابستگی مستقیم به Android جدا شد. `WireBase64` از Bouncy Castle موجود در پروژه استفاده می‌کند؛ وابستگی تازه‌ای اضافه نشد. خروجی استاندارد، بایت‌های دودویی، Unicode، نبود padding و فاصله‌های ASCII تست شدند. ورودی Base64 با alphabet یا padding خراب رد می‌شود؛ ادعای سازگاری با تمام ورودی‌های غیراستانداردِ قابل‌تحمل توسط decoder قدیمی نداریم.

اعتبارسنجی ساختار هش قفل اکنون مستقیماً به همان `LockHash.isValid` می‌رود؛ برای بررسی نحو هش، کتابخانهٔ JNI رمزنگاری بارگذاری نمی‌شود. الگوریتم هش و رمزنگاری قفل قدیمی در این تغییر عوض نشده است.

| بررسی اجراشده | نتیجه |
| --- | --- |
| `:app:testFullDebugUnitTest`، شامل کامپایل واقعی کد اصلی | موفق؛ ۳۰ تست، صفر شکست، صفر خطا و صفر skip |
| تست‌های corpus / Base64 / limiter در همین مجموع | به‌ترتیب ۸ / ۴ / ۷ تست؛ تعداد نمونه‌های ورودی corpus برابر تعداد تست‌های JUnit نیست |
| اجرای مستقل اسکریپت JVM | موفق؛ همان ۳۰ تست JUnit دوباره اجرا شدند، نه ۳۰ تست جدید |
| تست‌های قراردادی و شبکهٔ موجود در اسکریپت | موفق؛ از جمله importer/exporter، مدیریت نشست، HTTP/SOCKS محلی، TLS/SPKI و مسیریابی با Xray واقعی محلی |
| بررسی ترجمه | ۴۴۹ کلید قابل‌ترجمه، چهار زبان، قالب‌ها و جمع روسی؛ موفق |
| گارد افزایشی Kotlin | ۷۷ مورد موروثی، بدون افزودن مورد ممنوع تازه؛ موفق |
| ارجاع‌های پشتهٔ بستهٔ حذف‌شده و `git diff --check` | بدون ارجاع باقی‌مانده و بدون خطای whitespace |

تست استاندارد Gradle از استاب Android Base64 یا رمزنگاری استفاده نمی‌کند. اسکریپت JVM کمکی همچنان استاب‌های مرزی قدیمی برای قسمت‌های دیگر دارد؛ برای ثبت لاگ محدودکننده نیز همان استاب موجودِ لاگ را استفاده می‌کند. از این اسکریپت ادعای اجرای کامل runtime اندروید نداریم.

## محدودیت و کار باز

رمزگشایی قالب قدیمی `rovunet-enc://` به JNI وابسته است و در تست JVM این دور اجرا نشده؛ بعد از رمزگشایی، وارد همان dispatcher نسخه می‌شود. bundle رمزدار جدید در این دور واقعاً رمزگذاری و رمزگشایی شد. این بررسی، ادعای اعتبارسنجی همهٔ فیلدهای امنیتی خراب در تمام نسخه‌های تاریخی نیست. بعضی پارسرهای قدیمی هنوز فیلدهای انتهایی اختیاری و fallback دارند؛ سختگیرکردن همهٔ آن‌ها بدون نمونهٔ تاریخیِ تأییدشده می‌تواند سازگاری را بشکند و در این پیگیری انجام نشد.

در این دور شبیه‌ساز یا گوشی اجرا نشد، چون مسیر ترافیک native، MTU، چرخهٔ VPN و UI عوض نشدند. آزمون‌های موفق دستگاهِ review03 شواهد نسخهٔ قبلی‌اند و به‌عنوان اجرای مجدد این تغییرها گزارش نمی‌شوند. تغییر APK یا بازسازی native انجام نشد.

پنج کار قبلی باز می‌مانند: مسیر دادهٔ SOCKS و Soar+SSH روی سرور/شبکهٔ واقعی کاربر، اجرای GitHub workflow برای این سورس، هزینهٔ مهاجرت روی گوشی واقعی، تأیید تعاملی `known_hosts` در CLI و هویت امضای production همراه برنامهٔ مهاجرت نصب. برای انتشار عمومی هنوز نیاز به تأیید میدانی داریم.
