Rovunet 0.3.0-alpha02 — review and grouping changes

Grouping: account + origin-server evidence, explicit native metadata preferred.
Known DNS service subdomains may bridge protocols within one import. Resolver IP,
password, public key and shared CDN alone are not grouping identities. Ambiguous
anonymous paths remain separate. Import preview shows actual proposed collections.
Existing collections can be regrouped from the main menu after reviewing the plan;
this changes names/membership, not credentials. Manual group names may be replaced.
Compact cards expose group test, paths/edit, rename and move via a three-dot menu.

HTTPS verification: collection tests require a certificate-validated HTTPS 204
through the selected tunnel to www.gstatic.com. DNS scanner HTTP checks and DNS
resolver liveness are separate preliminary checks, not proof of a usable tunnel.
Probe failure categories/status codes are retained and logged without raw exceptions.

CI: build workflow now gates builds on JVM/HTTPS/lifecycle/Go contract/core integration.

AFTER publishing that manager commit. It exists locally only at delivery time.
Missing fixture, TLS store or core binaries fail CI instead of silently skipping.
Fixture is generated by the real Go GeneratePortableURI exporter test (not the CLI).
Workflow is authored and locally checked; no remote GitHub run has been observed.
