# Android 0.3.0-alpha13 private device candidate

The initial private delivery used application code 19. The [review02 follow-up](alpha13-review02.md) used private code 20. The [review03 follow-up](alpha13-review03.md) uses private code 21 and upgrades those test installations. Build the Full candidate with `-ProvunetDeviceCandidate=true -PveyraPrebuiltNative=true` and the normal Android build environment. The candidate installs as **Rovunet Test** (`app.veyra.client.candidate`) alongside the public app. It uses its own app storage and test signing identity. Public update checks are disabled in that package.

## What's being validated

- A selected connection starts directly. The VLESS WebSocket path accepts ordinary traffic once its local bridge is ready. An explicit HTTPS test verifies the remote path separately.
- A network change restarts the selected backend. Recovery handles failures after releasing its in-progress flag and mutex. Direct VLESS and SOCKS5 restart their actual bridges. Swiping away the activity preserves an established session.
- Resolver scans require the same previously approved SSH identity as a manual connection. Manual prompts are queued and an answer belongs to the displayed endpoint and fingerprint. Background scans do not ask to approve new keys.
- Xray uses an authenticated local SOCKS endpoint. VPN mode uses a per-session loopback port and credentials unless the user deliberately configured credentials. Proxy-only mode requires configured local credentials. Readiness checks the pinned child’s post-bind signal and the configured SOCKS handshake. XHTTP extra fields use a single-endpoint allow-list.
- Room 46 → 47 seals sensitive profile fields using a key generated by Android Keystore. DataStore migrates the local proxy password. Sharing a permitted profile still exports usable connection credentials. Encrypted, password-protected export is the appropriate option for confidential transfer.
- With IPv6 blocking enabled, the VPN advertises only IPv4 DNS to covered apps. The transport can still use its configured IPv6 resolver. With blocking disabled, full VPN mode routes IPv6 through TUN. DNS-only mode retains DNS-only routing.
- Production builds require the expected release certificate fingerprint (`ROVUNET_RELEASE_CERT_SHA256`) and a non-debug signer. The private candidate uses a separate test identity. Changing signer on the public package still requires a separately planned migration.
- Rebuilding the app's Rust engine through Gradle requires a non-zero 32-byte hex `CONFIG_ENCRYPTION_KEY`. The verified native assets reused for the candidate have the same hashes as alpha12. Locked portable links retain their existing compatibility model. A client-embedded key cannot enforce a user's subscription.
- The CLI checks TLS certificates and SSH host keys. Provision a verified host key in `~/.ssh/known_hosts`, or set `ROVUNET_SSH_KNOWN_HOSTS` to a verified file. The native scanner validates DNS response headers before indexing them.

The release decision requires actual traffic on the user's device and network. Desktop loopback, Android emulator traffic and a field test are separate evidence.
